# Opportunity web module

The opportunity portion of the LIHTC site-selection tool, built to drop into a larger web app.
It is plain JavaScript with one dependency, Leaflet 1.9, so it works whatever framework the host
uses (React, Vue, Svelte or none).

| Feature | What it does |
|---|---|
| **Map** | Colors metro Atlanta's 1,248 census tracts (2020) by opportunity tier, or by any single part (schools, jobs and so on). Shows past 9% applications, funded vs. not funded, and MARTA rail stations. |
| **Site profile** | Click a tract or an application, or search an address, tract number or project name. Shows the score, tier, the six part scores, a "strongest/weakest on" line, and the facts behind each part with their metro percentile. "Copy summary" puts a pitch-ready text summary on the clipboard. |
| **Weights** | One slider per part plus presets (Default, Families with kids, Seniors / no car, Workforce, Equal, and Access-focused, the earlier hand-set weights). The map and scores update live, and a readout shows how many tracts changed tier compared with the default weights. |
| **Advanced metrics** | Inside the Weights tab: every metric listed under its part, with an on/off switch and its own weight. Optional metrics (parks, broadband, HUD indices) start switched off. Any change from the default marks the score "custom" on the legend and the site profile. |
| **Compare** | Up to four sites side by side, with the best value in each row highlighted and lettered pins on the map. |
| **Method** | What each part measures, its sources and indicator weights, and the caveats. |

## Run it

**Easiest:** open `opportunity_site/standalone.html` by double-clicking it. It has the module and all the data
built in, so it needs no server, no unzipping and no terminal. Address search works too (it needs
an internet connection). It is regenerated by `python -m pipelines.opportunity.export_site`.

**For development**, serve the folder instead:

```bash
python -m pipelines.opportunity.export_site     # refresh opportunity_site/data/ from the processed tables
cd webapp && python -m http.server    # then open http://localhost:8000
```

The page has to be served over HTTP, because the module loads its data with `fetch`.

## Embed it

```html
<script src="https://cdnjs.cloudflare.com/ajax/libs/leaflet/1.9.4/leaflet.min.js"></script>
<script src="opportunity.js"></script>
<div id="opportunity" style="height: 100vh"></div>
<script>
  OpportunityModule.mount(document.getElementById("opportunity"), {
    dataUrl: "data/",                       // folder with the four files in opportunity_site/data/
    weights: null,                          // optional starting weights, e.g. {schools: 0.4, jobs: 0.3, ...}
    tiles: null,                            // optional basemap {url, attribution}; off by default
    initialTract: null, initialPoint: null, // optional opening selection
    initialCompare: [],                     // optional, up to 4 {tract, point: {lat, lon, label}}
    indicators: null,                       // optional metric weights, e.g. {park_dist_mi: 0.25, food_low_access_share: 0}
    onChange: ({ weights, indicators, isDefault, scores }) => {},  // scores: Map(tract -> {score, tier, index})
    onSelect: (profile) => {},              // a site was selected: {tract, county, score, tier, domains, facts}
  }).then((opp) => {
    // opp.selectTract(id), opp.setWeights(w), opp.getWeights(), opp.setIndicators(m), opp.getIndicators(), opp.getScores(),
    // opp.getProfile(id), opp.addToCompare(id, label), opp.map (the Leaflet map), opp.destroy()
  });
</script>
```

The same two events are also dispatched on the mount element as `opportunity:change` and
`opportunity:select` (`CustomEvent`, payload in `event.detail`).

**Connecting to the rest of the tool.** The host app owns the combined score from the project
notes (fundability vs. need slider). This module supplies one input to it: `opportunity_score`,
0–100, for every tract, under the user's current weights. Everything is keyed by the 11-digit
2020 census tract GEOID (`tract_2020` in the processed tables), so need and fundability scores
should use the same key.

**Styling.** Styles are injected once and scoped under `.opp`. Colors and fonts are CSS custom
properties on `.opp` (`--opp-accent`, `--opp-font`, `--opp-t0` … `--opp-t4` for the tier ramp, and
so on), so the host can override them. Light and dark themes follow `prefers-color-scheme` and a
`data-theme="light|dark"` attribute on `<html>`. The tier ramp is one blue hue, checked for
color-vision deficiency and contrast in both themes.

**Address suggestions** appear as you type, from [Photon](https://photon.komoot.io) (an open
geocoder built on OpenStreetMap data, limited to the metro Atlanta area). A picked suggestion is
placed at its own point. Hosts with a strict Content-Security-Policy need to allow
`connect-src https://photon.komoot.io`. Credit "© OpenStreetMap contributors" shows under the
suggestions.

**Full addresses typed and looked up "as typed"** use the U.S. Census Bureau geocoder, the same one the pipeline used to place
applications, so a typed address lands in the same tract as the historical data. It is called
with JSONP, because the geocoder doesn't send CORS headers. Hosts with a strict
Content-Security-Policy need to allow `script-src https://geocoding.geo.census.gov`. If the lookup
is blocked, the module says so and users can still click the map or search tract numbers and
project names.

**Scoring** in the browser matches `pipelines/opportunity/build_opportunity.py` exactly: a weighted mean of the
six part scores, re-ranked to a 0–100 percentile across metro tracts, then quintile tiers. With the
default weights the browser's scores equal `opportunity_score` in the processed tables for all
1,245 scored tracts.

## Data files (`opportunity_site/data/`, written by `pipelines/opportunity/export_site.py`)

| File | Size | Contents |
|---|---|---|
| `tracts.geojson` | 2.3 MB | Tract outlines (simplified to about 30 m), part scores, profile facts, indicator percentiles |
| `applications.json` | 50 KB | 218 metro 9% applications with a tract: year, name, funded or not, location. 28 whose coordinates were missing or failed the county check are placed at their tract's center. |
| `meta.json` | 10 KB | Default weights, presets, part descriptions and sources, indicator weights, caveats |
| `places.json` | 4 KB | MARTA rail stations and county label points, so the map reads without a basemap |
